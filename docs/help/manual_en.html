Get started

Requires QGIS 3.44 or newer 3.x/4.x.

The plugin prepares classified forest polygons and indicators for a separate value-table model. Open the wizard from the plugin toolbar or plugin menu.

  1. Run Set up forest planning layers in the wizard toolbar.
  2. Check that all eight required sources are ready.
  3. Choose an analysis area and an output folder.
  4. Press Run and follow progress.
  5. Review the map results and workbook, including coverage and limitations.

This manual and the licence texts work offline. Source setup and analysis need an internet connection to the configured data services.

Open this manual with the wizard's Help control or Help → Plugins → Savonia - Responsible Forest Planning: Help. About shows the installed version, credits and licences. Both are available with the wizard closed.

The interface, help and new outputs follow QGIS's application language: Finnish for Finnish QGIS, English otherwise. Change the language in QGIS settings and restart as prompted. An already open browser manual keeps its language.

Prepare the project

Setup first requires an MML API key. Cancelling or leaving it blank stops setup before any layers change. The key is remembered in QGIS settings and used as the layer connection username with an empty password. This authenticates discovery and feature requests without another credential prompt when the key is valid. Saved projects retain the key as username. To replace a rejected key, change or clear savonia-forest-planning/mml-api-key in QGIS's Advanced Settings Editor, then repeat setup. After updating the plugin, repeat setup to refresh existing MML connections. Review saved project connections before sharing.

References contains Property boundaries, Forest inventory, Protected areas and Water, in that order. Property boundaries contains unfilled red boundaries with 1 mm outlines and no polygon labels, followed by Property identifiers: red 20-point kiinteistotunnuksenEsitysmuoto labels with a white 2 mm text buffer from MML's identifier points, with no point symbols. Boundaries appear at 1:25,000 or closer; identifiers at 1:10,000 or closer. Forest inventory contains habitats, stands and grid; Protected areas contains programmes, wilderness, state-owned and private-land areas, all using the same translucent rose fill and outlines matching groundwater's treatment. Water contains groundwater. Repeated setup restores managed styles and order while preserving user layers and visibility choices. Both MML layers provide map context; the eight analysis sources and exported snapshots remain the same. A failed MML connection leaves setup incomplete; check the key and network connection and repeat setup.

Choose Set up forest planning layers, the first action in the wizard toolbar, or run it from the plugin menu. Opening the wizard alone does not prepare the sources. Setup creates or reuses Results, References and Basemaps groups and the required source layers. You can repeat setup without duplicating managed layers. Setup checks WFS service descriptions and fields without downloading sample features. Map data is requested for the visible area; analysis data is requested for the analysis area in pages, without a total feature limit. After updating the plugin, repeat setup to apply the optimized connection settings to existing layers. Slow service-description responses can still delay setup.

Setup asks for a SYKE sykeuserid. A blank value is accepted and you can supply one by running setup again. For sustained or intensive application use, request an application-specific identifier from SYKE geospatial support. The identifier is saved in QGIS settings and service URLs, including URLs in saved QGIS projects. Review it before sharing a project.

Basemaps contains Orthophoto, Topographic map and OpenStreetMap in that order. The two MML maps use ETRS-TM35FIN and the same saved MML API key as parcels. When Topographic map is first added, it is visible and the other managed basemaps are hidden. Later setup preserves your visibility choices. Toggle their checkboxes to change the background. An unavailable basemap is reported separately from analysis-source readiness. Basemaps provide display context only. Stands and habitats appear at 1:7,763 or closer; the grid has dark green borders with no fill and appears only at 1:300 or closer. These display limits do not affect analysis. Keep the configured References layers available and correct any reported readiness failures before running.

Sources and readiness

All eight configured online source layers are required. Setup checks their connection, geometry, coordinate system and required fields. A ready source can still contain values that fail analysis; follow the reported source error if this happens.

SourceUsed for
Metsäkeskus forest standsForest boundaries, total volume, sawtimber, growth and optional tree basal area.
Metsäkeskus forest habitatsSection 10 and other valuable habitat classification.
Metsäkeskus forest inventory gridGrid volumes, age shares, peatland and natural-mire area indicators.
SYKE state-owned protected areas, private-land protected areas and wilderness areas (three layers)Protected-area classification.
SYKE nature conservation programme areasProgramme-area classification and context.
SYKE groundwater areasGroundwater-area classification.

Use the configured layers created by setup. Renaming another layer or matching its field names does not make it a supported source. Source data are clipped to the chosen area; the original layers are preserved. Successful retrieval, including an empty response, does not prove complete geographic coverage.

Analysis normally requests features intersecting the actual area polygon, including holes and separate parts, to reduce unnecessary downloads. Large polygon filters use the area's bounding rectangle instead; exact local clipping and complete paging are retained. Source coverage records the query strategy. The grid snapshot covers the chosen area, including land outside the forest stands. Returned invalid polygons are repaired when possible; remote filtering cannot recover malformed features omitted by the service.

Choose the analysis area

  • Use an existing polygon layer: choose a layer and inspect Use selected features only and the selection count. With a selection, the wizard initially checks this option automatically; you can uncheck it to use all features. An automatic choice clears if the selection disappears. An explicitly checked choice stays checked with an empty selection and disables Run until you select features or uncheck it. Check the area status again after changing the selection. When selected-only mode is used and this layer is also a configured source, its selected geometry and attributes are captured as a local analysis snapshot.
  • Draw an area on the map: press Draw analysis area, click at least three vertices with the left mouse button and finish with the right button. The polygon appears as Drawn analysis area. A newly completed polygon replaces the previous drawn area; Clear drawn area removes it. Drawing fewer than three vertices leaves the previous area unchanged.
  • Use the current map extent: the extent is captured when analysis starts. Set the view before running. Layer-selection controls apply only in the existing-layer mode.

The area must contain valid, nonempty polygons with a correctly assigned coordinate system. Overlapping area features are combined. Results use EPSG:3067 and hectares. Invalid area geometry or a failed coordinate transformation stops the run.

Use the wizard

Unloading or disabling the plugin requests cancellation of its active analysis. Completion after unload does not add results to the project.

Choose an area mode, check the area/selection status, enter a positive Sawlog stumpage price (€/m³) with two decimal places, choose a writable output folder and press Run. Price follows the area controls and comes before the folder. With no saved price it starts blank; the last valid price and folder are remembered across projects and restarts. Clearing the current price prevents a run. Run becomes available only when the area, required sources, price and destination are ready and no run is active. Each run generates a new output name.

Follow progress in QGIS's task manager. Cancel analysis requests a stop; wait for cancellation to finish. Close hides the panel and preserves its choices. Use the separate Cancel analysis button to stop a run. A detached panel can be moved back with Redock panel to right. Help and About work in both modes.

After success, the wizard adds the run's tier/class views and source snapshots beneath Results. The GeoPackage and workbook paths appear in the completion message. Follow Map review to inspect the views; check coverage and classification before using the results elsewhere.

Processing Toolbox

With selected-only mode and an AOI that is also a configured source, both entry points use a local copy of the selected geometries and attributes. The wizard captures that copy when the run starts; later changes to the selection do not change that run.

As an alternative to the wizard, run savonia_forest_planning:prepare_forest_scenario_inputs in the Processing Toolbox. It uses the same analysis rules and also supports batch and model workflows. Its Help link opens this section.

The algorithm returns the classified GeoPackage layer (RESULT) and workbook path (EXCEL). Open these to inspect the results. The grouped tier views described below are added by the wizard; other GeoPackage layers and tables can be added from QGIS's Browser panel.

Read the results

Each successful run writes a .gpkg and .xlsx with the same basename. The GeoPackage holds the classified forest polygons, clipped source snapshots, source coverage and run metadata. The workbook summarizes indicators separately for each tier and class.

Map review

Expand the run beneath Results. Each of its six tier groups contains checked Sensitive (red/orange), Economic (green) and Unknown (grey) views. Initially only the All out group is enabled. Turn the current tier group off and the desired group on to reveal its checked children. These eighteen filtered views use the same result dataset.

Open a view's attribute table or identify a feature to inspect its indicators and all six class fields. Ordinary check attributes report protected areas, Section 10 parent promotion, programmes, groundwater and other valuable habitats as Match, No match or Unknown. Section 10 can match outside the mapped habitat footprint because it describes the whole parent. Input snapshots used contains checked clipped-evidence layers inside an initially hidden group; enable the group to reveal them. Earlier runs and References remain available. To view all result polygons together, add classified_forest_polygons from the run's GeoPackage through the Browser panel.

Six sensitivity tiers

TierSensitive when
All out, BAU, LightAn active protected area overlaps the piece, or a qualifying Section 10 habitat hit promotes its parent stand. These three tiers currently use the same criteria.
BalancePrevious criteria, plus programme or groundwater areas.
ProtectionBalance criteria, plus other valuable habitats.
SuperprotectionAll analyzed forest is sensitive when required evidence is available.

A sensitivity hit requires more than 1 m² of overlap; boundary contact or exactly 1 m² does not qualify. A Section 10 hit makes all pieces of the same original stand sensitive in the applicable tiers. Unknown means insufficient evidence. The current workflow stops before publication if a required source fails; a successful empty response can permit a no-hit classification.

Result polygons of 0.01 m² or less are excluded before indicator calculation and summaries. The run reports their count and total area and stores these in run metadata; clipped source snapshots remain available. Larger polygons are retained even if their hectare value rounds to zero. If every result polygon is excluded, the run stops without publishing outputs.

Indicators and units

IndicatorMeaning
Land area (ha)Classified forest area within the chosen area; 1 ha = 10,000 m².
Stand total and sawtimber volume (m³/ha)Stand estimates weighted by result-piece area.
Stand growth (%/year)Stand annual volume growth relative to positive stand volume, averaged by area. The exact growth period/basis remains a source limitation.
Stand tree basal area (m²/ha)Trunk cross-sectional area at breast height per land hectare, when available. This is different from land area.
Grid total, pine, spruce and deciduous volume (m³/ha)Separate estimates weighted by actual intersected area with valid values. Deciduous includes all deciduous trees, not birch alone.
Grid age shares (%)Area with mean age under 20, 20–80 inclusive, or over 80, divided by area with valid age.
Peatland and source-classified natural-mire area (ha)Source soil/drainage classifications within analyzed forest, without certifying present ecological condition.
Sawlog stumpage price (€/m³)Your supplied unit price where original stand sawlog volume is valid and positive; otherwise blank. Groups weight by unrounded represented sawlog cubic metres, so every eligible group has the supplied price. This is neither an all-timber price nor a total valuation; pulpwood pricing is outside scope.
Calculated sawlog value (€)Unrounded represented stand sawlog m³ multiplied by your €/m³ price. Known zero stock gives €0; missing or invalid stock stays blank. Complete group totals sum exact amounts before rounding to cents. Incomplete and empty group totals stay blank; Metric coverage retains the known euro subtotal in weighted_sum. This is a sawlog-only amount, not a whole-forest value or income forecast.

Blank is not zero. Partial density means and age shares describe only valid data; inspect valid and unknown hectares. Peatland/mire totals stay blank if any area is unknown; observed matching area is a lower bound. Stand and grid volume estimates remain separate. Species means can have different coverage and need not sum to grid total.

Volumes are rounded to whole m³/ha, hectares to 0.01 ha, and age shares to whole percentages. Other decimal results display two decimals. Summaries use full-precision values before rounding. Age shares may sum to 99% or 101%, and small positive areas may display as zero. Reporting precision does not imply measurement accuracy.

Keep price and value units separate: 506.268850 m³ at 10 €/m³ gives a calculated sawlog value of €5,062.69, while the unit price remains 10 €/m³. The price parameter is per cubic metre of sawlogs, not per square metre of land. Calculated euro amounts are stored to cents; exact subtotals remain in Metric coverage. Overlapping stands can duplicate monetary contributions as well as area and stock.

Interpretation limits

Overlapping forest stands remain in the results without trimming, regardless of overlap size. A successful-completion warning gives the technical log destination. Areas and timber contributions can be counted more than once; pairwise overlap areas do not measure unique overlapping ground. The parent-overlap attribute applies to every piece of an affected stand, even outside the physical overlap. Shared boundaries and overlaps outside the analysis area do not trigger it. Conflicting inventory grid cells still stop publication.

  • Results describe forest represented by the stand source, not the whole analysis area. Open mires outside those stands are excluded.
  • These are descriptive inputs for a separate model. They do not calculate scenario impacts, prescribe forest operations or establish legal harvesting rights. Programme areas provide historical planning context; check current authoritative decisions and field evidence before operational use.
  • Water buffers, recreation, potential protected sites, MY areas and peatland sensitivity criteria are outside this version. Groundwater classification and peatland/mire indicators are included.
  • Source coverage, metric coverage and source dates matter. Grid values are assumed uniform inside each cell; clipping does not improve observation accuracy. Measurement dates differ from database update and retrieval dates.

Troubleshooting

ProblemAction
Source not ready, missing fields or request failureCheck internet access, QGIS network/proxy settings and provider errors, then repeat setup. Use the configured References layers. For slow requests, try a smaller area.
Invalid area or coordinate transformationRepair the polygon in a separate copy and check its correct assigned coordinate system, then select it again.
Unrepairable source geometry, conflicting grid cells or unrecognized classification valuesRead the reported source and IDs, refresh setup and report the problem with a small reproducible area. Required-source errors stop publication.
Run remains disabledCheck the current area/selection, configured sources, positive sawlog price and writable output folder. A cleared price cannot reuse the saved value silently.
Stand overlap warning after successInspect affected parent flags and technical-log stand IDs. Results retain duplicate area/timber contributions; decide whether to correct the source geometry before using summaries.
Blank or partial indicatorCheck Metric coverage and source dates. Do not replace missing values with zero or another source estimate.
Output cannot be written or already existsChoose a writable folder and a new valid basename. Close applications holding output files.
Write failure or cancellationThe workflow tries to remove both partial outputs. Check the directory before retrying; locked files can prevent cleanup.
Help or notices missing / browser does not openCheck your default browser or open the packaged manual directly. If files are missing, reinstall the complete plugin ZIP. An unavailable online link does not prevent local help.

For diagnostics, open QGIS View → Panels → Log Messages and select the plugin's tab. Detailed technical.log files are in savonia_responsible_forest_planning_tool/logs/ under QGIS's user settings directory. Include the installed plugin version, QGIS version, run ID, failed stage and reproduction steps in a bug report. Remove credentials, service identifiers and unnecessary personal/source data before sharing logs.
