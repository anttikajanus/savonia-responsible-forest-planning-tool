Workflow

The plugin prepares classified forest polygons and indicator inputs for a separate Savonia value-table model. It does not calculate scenario impacts, approve forest operations, or make legal determinations. The wizard and Processing Toolbox invoke the same analysis workflow.

  1. Install and enable the plugin. It follows the QGIS application language: Finnish when QGIS uses Finnish, and English otherwise.
  2. Run Set up forest planning layers. Check that all eight required sources are ready.
  3. Choose a polygon analysis area and an output folder in the wizard, or supply the corresponding Processing parameters.
  4. Run the analysis. Follow progress and resolve reported validation or source failures.
  5. Review the classified layer, GeoPackage and workbook, including source coverage, metric coverage, limitations and data attribution.

This manual and licence texts work offline. Managed source discovery and analysis fetch online WFS data and need network access. Having offline documentation or previously displayed map features does not make remote analysis available offline.

Choose Help → Plugins → Savonia - Responsible Forest Planning: Help or use the wizard's Help control. Savonia - Responsible Forest Planning: About is in the same menu and is also available before opening the wizard. Help follows the QGIS application language, with English as the fallback for unsupported languages. To change the language, change QGIS's application language and restart QGIS as prompted. The manual opens in your system browser. An already open browser page keeps its language until another launch.

Installation and runtime

The plugin's language selector has been removed. A language saved in an older version is ignored; you do not need to reset plugin settings. The interface, help and new outputs follow QGIS's application language.

The packaged metadata targets QGIS 4.2.3 and newer 4.x releases, with minimum 4.2.3 and maximum 4.99. QGIS 4.2.3 is the current verification baseline; later releases need runtime checks as they become available. Use the selected QGIS runtime's bundled Python, PyQGIS, Qt/PyQt and data providers. No separate Python packages or spreadsheet library are required.

Install a complete plugin ZIP. To build it from source, keep the full repository checkout, including docs/help/, and run this command in Windows PowerShell from the repository root:

./qgis_plugin/package.ps1

The command preserves the version in metadata.txt and writes or replaces its ZIP in qgis_plugin/dist/, printing the archive path. In QGIS open Plugins → Manage and Install Plugins → Install from ZIP, select that ZIP and enable Savonia - Responsible Forest Planning. A supplied complete ZIP can be installed through the same menu without building it. The ZIP contains the savonia_responsible_forest_planning_tool directory at its root, both manuals, licences and notices. Open Help to check the manual; the installed version appears in About and Plugin Manager.

Release maintainers: qgis_plugin/package.ps1 -BumpMinor edits metadata.txt, increments the minor version and resets the patch to zero before building. Use it when intentionally preparing a new version.

For development, keep the complete checkout and link its package directory into a separate QGIS profile using a Windows directory junction, or set QGIS_PLUGINPATH to the checkout's qgis_plugin directory before starting QGIS. The repository's docs/architecture/development.md gives the setup and reload steps. Source-linked development opens the repository manuals in docs/help/; copying only the source package directory omits them. Use the QGIS runtime for Python checks and Plugin Reloader after edits.

Project setup

Open the wizard from the plugin toolbar, then use Set up forest planning layers, the first action in the wizard toolbar. It remains available when the wizard is detached. You can also run setup from the plugin menu with the wizard closed. It creates or reuses localized Results, References and Basemaps groups, discovers WFS feature types and schemas and creates the eight configured source layers. Repeating setup reuses managed layers. Keep those identities and endpoints intact; renaming a display label does not replace source verification.

On first setup, supply an application-specific SYKE sykeuserid, or leave it blank to continue. The plugin accepts a blank value, but SYKE requires an application-specific identifier for long-term application use or intensive requests. Request one from SYKE geospatial support. It is saved in QGIS settings and included in SYKE WFS layer URLs and requests. Saving the QGIS project also stores those layer URLs, including the identifier, in the project file (.qgs or .qgz). This is intended behavior so saved layers retain their service connection details. Review the identifier in layer URLs before sharing a project. Metsäkeskus does not use it. Run setup again to save an identifier later.

OpenStreetMap is display context in Basemaps. Stands and habitats render at 1:500,000 or closer. The grid is the bottom References layer and renders only at 1:300 or closer. These visibility limits do not restrict analysis. Ranta10 is disabled. If setup reports not ready, correct the source problem before running.

Required sources and source schema readiness

All eight configured sources must use the WFS provider and be valid polygon layers with a valid CRS, matching service identity and required provider fields. Schema readiness checks field presence case-insensitively; extra fields and field order are allowed. It does not validate field types or certify every attribute value. Saved discovery schemas are provenance; current provider fields determine readiness and field mappings.

All sources are required; the protected-area group comprises three layers.

Analysis requests features within the AOI bounding box and clips them exactly to the AOI. Sources remain unchanged. Invalid source polygons are repaired with QGIS makeValid() where valid polygon components can be retained; repair counts and source ID samples are reported. Null, empty, unrepairable, failed transformed/clipped geometries and request/overlay failures stop publication.

Choose the analysis area

  • Project polygon layer: choose a layer and explicitly check whether only selected features should be used. Selected-only mode requires a nonempty selection. When this layer is also a configured source, selected geometry and attributes are captured as a local analysis snapshot.
  • Draw polygon: click at least three vertices with the left mouse button and finish with the right button. Clear and redraw when needed.
  • Current map extent: the extent is captured when analysis starts. Set the view before running.

The AOI must have valid, nonempty polygon geometry and a usable CRS. Overlapping AOI features are dissolved. All source and AOI geometry is explicitly transformed to EPSG:3067; areas use planar square metres divided by 10,000 to give hectares. Invalid AOI geometry or a failed transformation stops the run. No distance buffers or proximity rules are used.

Use the wizard

Open the persistent wizard with the plugin toolbar action. The current wizard has one analysis page: choose an area mode, inspect the area/selection status, choose an output folder and press Run. The folder choice is remembered in QGIS settings. There are no additional pages to complete in this version.

Keep the configured layers in References available. The wizard captures source inputs before starting its background task. Follow Processing progress; Cancel requests a stop at safe checkpoints. Close hides the panel; use its redock action when detached. Help and About remain available in either mode. The QGIS application language governs help, messages and new output presentation.

After success, the wizard adds the run's classified results, tier views and source snapshots beneath Results. The GeoPackage and workbook paths appear in the completion message. Inspect both coverage and classification before using the results elsewhere.

Processing Toolbox

Run savonia_forest_planning:prepare_forest_scenario_inputs in the Savonia group. It calls the same validation, retrieval, classification, calculation and publication workflow as the wizard. Its short help follows the QGIS application language; its Help link opens this offline section. It can also be used through Processing batch/model tools with the same required inputs.

Outputs, classification and units

A successful run writes one .gpkg and one .xlsx with the same basename. The GeoPackage contains classified_forest_polygons, AOI-clipped source snapshots, source_coverage and run_metadata. Results retain source/rule IDs, area, six tier fields, indicator status fields and full-precision indicator_coverage JSON. The workbook contains localized tier/class summaries, source coverage, metric coverage and calculation notes/run metadata. Both outputs retain data attribution, terms links and the modifications notice.

Six sensitivity tiers

Machine fields are class_all_out, class_bau, class_light, class_balance, class_protection, class_superprotection. Values are SENSITIVE, ECONOMIC or UNKNOWN. Direct sensitivity requires intersection greater than 1 m²; boundary contact or exactly 1 m² does not trigger a hit. Protected/programme/other-habitat triggers apply to overlapping pieces. A Section 10 hit promotes every output piece of that original stand.

TierTriggers
All out, BAU, LightActive protected area or Section 10 habitat stand promotion; identical criteria stored separately.
BalancePrevious triggers plus programme and groundwater areas.
ProtectionBalance plus other valuable habitat.
SuperprotectionRecognized triggers and all remaining analyzed forest are sensitive when the required evidence is available.

Unknown classification means evidence cannot establish a result, never an economic default or zero. Without a recognized positive hit, a tier can be ECONOMIC only when required evidence is available. Current analysis stops before publishing if a required source fails validation, retrieval or interpretation. A successful empty source response is marked AVAILABLE and currently permits a no-hit classification; this does not prove full real-world coverage.

Birch-only volume is not calculated or published as a separate field in this version; the grid provides all deciduous trees together. Deciduous volume must not be labelled or interpreted as birch-only volume.

Grid numeric values must be finite nonnegative numbers. Null, text, booleans, negative and nonfinite values are unavailable; zero is valid. Every metric keeps its own valid and unknown hectares. Partial density means describe valid area only; missing cells or values do not become zero or stand-based substitutes. Species means can have different denominators and need not sum to grid total. Measurement date is distinct from database update/retrieval time.

Volume fields are published as whole m³/ha, hectare fields at 0.01 ha, with halves rounded up. Other decimal presentation uses two decimals; age shares/age coverage/counts are whole numbers. Coverage statistics and summary inputs retain full precision and summaries are rounded after aggregation. Small positive areas may display as zero. Reporting increments do not state measurement accuracy.

Assumptions and limitations

  • The reporting domain is classified forest polygons from the stand source. Open mires outside those stands are not automatically included. Source-classified natural mire does not certify ecological condition; mire/peat indicators do not alter sensitivity tiers.
  • Programme areas provide indicative historical planning context, not legal proof. Check current authoritative decisions and field evidence before operational use.
  • Forest-sensitive water, peatland sensitivity criteria, water-protection buffers, recreation, potential protected sites and MY areas are OUT_OF_SCOPE; they are not requested or processed. Groundwater is included. No proximity/buffer rule is applied.
  • Successful requests, returned feature counts and empty results do not certify geographic completeness. Unknown classification and unknown metric area are different concepts; inspect both.
  • AOI overlaps are dissolved. Distinct clipped stand overlaps greater than 1 m² stop the run. Smaller overlaps remain untrimmed and can contribute to both stands. Identical same-ID grid records are deduplicated; conflicting IDs or positive-area overlaps of distinct grid cells stop publication. Shared edges are allowed.
  • Positive indicator intersections above 1e-8 m² are retained, including genuine fragments smaller than 1 m². This storage tolerance is separate from the sensitivity-hit threshold.
  • Managed sources use WFS 2.0. QGIS 4.2 does not detect legacy WFS 1.0 ServiceExceptionReport responses reliably; custom legacy services may appear empty. Use the managed configuration.
  • Online services can change schema, values, availability and dates. Retained snapshots and metadata describe the run's evidence, not a guarantee of provider completeness or current legal status.

Troubleshooting and recovery

SymptomAction
Setup not ready / source missing / required fields missingCheck internet access and source provider errors, run setup again, and use the managed References layers. A renamed or arbitrary layer does not replace a configured source. Do not delete fields to bypass readiness.
WFS request fails or hangsCheck the service and network/proxy settings. Use a smaller AOI to diagnose volume, then retry. For SYKE, check the identifier setup and provider requirements above. An empty successful response cannot establish full coverage.
Invalid AOI / CRS or transform errorRepair the input polygon in a separate copy, check its correct assigned CRS and available transformations, then select it again. Do not assign a different CRS merely to force alignment.
Unrepairable source geometry, overlapping stands/cells or unknown category valuesRead the reported source/IDs and diagnostic stage. Refresh source setup, verify source data, and report the defect with a minimal reproducible area. Analysis stops rather than publishing fabricated classifications.
Blank or partial indicator / UNKNOWNInspect source coverage, indicator status and valid/unknown hectares. Missing evidence is not zero. Check dates and current provider values; do not fill missing values from another source estimate.
Output not writable / existing outputChoose a writable folder with an existing parent and a new valid basename. Close applications holding the output files. Existing runs are never overwritten.
Write failure or cancellationThe workflow attempts to remove both partial outputs. Verify the directory before reusing a basename; cleanup can itself fail on locked files. Retry only after resolving the original error.
Help/notice file missing or browser launch failedReinstall the complete plugin ZIP, verify the packaged docs/notices and configure a working system browser. Open the packaged manual directly as a recovery step. An unavailable online link does not affect local help.

Technical diagnostics use the QGIS log panel's plugin tag and a rotated UTF-8 technical.log under savonia_responsible_forest_planning_tool/logs/ in QGIS's user settings directory. Separate business-actions.jsonl files hold local aggregate operation records, not telemetry or durable result provenance. Each log is limited to 2 MiB plus three backups. Use run metadata for reproducible analysis evidence. When reporting errors, retain the run ID and stage and remove credentials or unnecessary source/personal data. If the log location is unavailable, inspect the QGIS log panel.
